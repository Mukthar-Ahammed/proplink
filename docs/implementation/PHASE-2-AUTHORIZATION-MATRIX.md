# Phase 2 authorization matrix

Verified against the Phase 2 working tree on 2026-10-08. This records enforced Phase 2 behavior; it does not grant a planned feature merely by documenting it.

## Legend

- `ALLOW` — permitted without record ownership because the data/action is public or governance-scoped.
- `OWN` — permitted only for records belonging to the authenticated actor.
- `ASSIGNED` — permitted only when the server proves the actor owns the listing/AgentProfile or is a participant in that exact marketplace context.
- `APPROVED_KYC` — requires authoritative `profiles.kycStatus = APPROVED` in addition to role, subtype and ownership/state checks.
- `DENY` — explicitly forbidden.
- `NOT_IMPLEMENTED` — no application operation exists; RLS/client access must remain denied.

`Flipper`, `Syndicate`, and `Both` below are all primary role `INVESTOR`, distinguished by authoritative `profiles.investorType`. An Investor with `investorType = NULL` receives no subtype-specific permission. Public/ordinary non-financial Investor actions are called out explicitly.

## Enforcement locations

- Server identity and active/mapping consistency: `src/lib/auth.ts` via Supabase `auth.getUser()` plus authoritative Profile and legacy compatibility checks.
- Authentication audience separation: `/login` for Buyer/Agent/Investor and `/admin/login` for Admin, enforced after authentication in `src/app/(auth)/actions.ts`; page differences are not the security control.
- Composable role/subtype/KYC checks: `src/lib/authz.ts` and `src/services/syndicates/investorType.ts`.
- Resource ownership/state: domain services under `src/services/listings`, `enquiries`, `agents`, `offers`, `viewings`, and `chat`.
- Browser/Data API defense in depth: the Phase 2 successor RLS migration, using `auth.uid()` and private fixed-`search_path` helpers.
- Optimistic navigation only: `src/proxy.ts`; Proxy is never the sole authorization control.

## Public data boundary

- Property pages expose listing marketing fields, address, price, bedrooms/type, EPC, disclosed distress tags, images, target ROI, map coordinates, public status and the linked public Agent card. They do not expose Profile, User, enquiry, offer, viewing, message, save or KYC rows.
- Public Agent profiles expose agency name, bio, compliance code, aggregate rating/count, completed-deal count, case studies, appraisal rating/review/date, and currently the reviewer's display name. They do not expose reviewer email, Profile UUID, KYC, role, activity state or private marketplace records.
- Reviewer display names are existing product behavior. A privacy/product decision is still required on whether to replace them with an abbreviated or anonymous label; Phase 2 does not silently change this policy.
